# CLAUDE.md — NoCook agent instructions

You are building **NoCook** for the Eternal Hackathon Showcase 2026: a service that makes a Zomato order cancellation reach the restaurant kitchen as a **time-bounded human acknowledgement**, with escalation (takeover at +30 s, mock IVR call at +75 s, expiry at +10 min) and a server-side audit trail.

The deliverable judges see is **live Grafana dashboards (p50/p95/p99 vs SLO lines) under real load, while faults are injected, with zero safety-invariant violations**. Every decision below serves that.

Read this file fully before every task. Then read the task in `TASKS.md` and every doc it links. Docs are the spec; do not invent behaviour they don't describe.

## 4. How to work a task

1. Read the task block in `TASKS.md` (ID, owner, depends, spec links, "Done when").
2. Check its dependencies are ticked. If not, stop and say which one blocks you.
3. **Tests first** for anything in `nocook-domain`, any race/invariant, and any API contract. Write the failing test, then the code.
4. Implement the smallest thing that satisfies the spec. No speculative features.
5. Run every command in "Done when". Paste their tail output in your final message.
6. Tick the box in `TASKS.md` (`- [x]`), and add one line under the task: what you built + anything surprising.
7. Commit: `git commit -m "B-04: deadline worker with SKIP LOCKED leases"`. One task per commit where practical.

Slash commands in `.claude/commands/`: `/task <ID>`, `/gate <G0..G4>`, `/verify`.

## 5. Non-negotiable rules (breaking one fails the demo)

1. **NoCook never mutates OMS state.** It reads OMS only through `GET /oms/api/orders/{id}`. The `nocook_app` DB role has no privileges on schema `oms`.
2. **Every side effect is a durable intent first.** Card sends, takeovers and calls are rows in `nocook.outbox` written in the same transaction as the state change. Dispatch happens after commit.
3. **Every escalation re-reads OMS** (fresh HTTP call, no cache). If OMS is unreachable, **defer** (fail closed). Never escalate on stale state.
4. **Uniqueness enforces safety, not code paths:** `UNIQUE(order_id, order_version)` on cases, partial unique open case per order, `UNIQUE(case_id)` on `call_attempts`, `UNIQUE(action_key)` on outbox, `UNIQUE(case_id, kind)` on deadlines. Catch the violation, count it, move on.
5. **Transport receipt ≠ human ACK.** MQTT PUBACK, RabbitMQ ack, tablet DELIVERED/RENDERED receipts are facts. Only `POST /api/cases/{id}/ack` or a verified DTMF webhook closes a case as ACKNOWLEDGED.
6. **Time comes from an injected `java.time.Clock`.** No `Instant.now()`, `LocalDateTime.now()`, `System.currentTimeMillis()` in domain or service code. SQL takes `:now` as a parameter (no `now()` in decision queries).
7. **No `Thread.sleep` in tests.** Advance a `MutableClock` and call the worker's `tick()` directly. Awaitility only for broker/MQTT round-trips.
8. **Metric names are a contract.** Use exactly the names in `docs/OBSERVABILITY.md`. Dashboards depend on them.
9. **Labels on numbers:** anything shown to judges carries `MEASURED`, `TESTED` or `SIMULATED`, plus N and run ID.
10. Do not add Kafka, Redis, Kubernetes, Temporal, JPA/Hibernate, Lombok, or the OTel Java agent.

## 6. Code conventions

**Java**
- Package root `com.nocook`. Modules: `com.nocook.domain`, `com.nocook.service`, `com.nocook.oms`, `com.nocook.sim`.
- Java `record`s for DTOs, events, facts. `sealed interface` for command/effect/outcome hierarchies. `switch` pattern matching over sealed types.
- Constructor injection only. No field injection. No Lombok.
- Persistence: Spring `JdbcClient` + hand-written SQL in `*Repository` classes. No JPA.
- One transaction boundary per use case, in `application` services (`@Transactional`). Repositories never open transactions.
- Name variables for what they hold (`dueDeadlines`, `freshSnapshot`), never `res`, `tmp`, `data`. Write code structurally: no clever one-liners, no nested ternaries, small methods.
- Logging: SLF4J, structured key=value (`caseId=… state=…`). Never log customer PII (there is none in the mock, keep it that way).
- Virtual threads: `spring.threads.virtual.enabled=true`.
- Errors: domain returns outcomes, not exceptions. Controllers map outcomes to HTTP codes per `docs/API.md`.

**TypeScript**
- `strict: true`, no `any`, no default exports except route components.
- Server state via TanStack Query; MQTT state via one `useMqtt` hook; no global state library.
- Tailwind only, no CSS-in-JS.

**SQL**
- Lower-case keywords, snake_case, explicit column lists, `timestamptz` everywhere.
- New migration = new file `V{n}__{what}.sql`. Never edit an applied migration after G1.

## 7. Commands you will use

```bash
make up            # build + start full stack (3 nocook replicas)

make ps / make logs S=nocook-1
```
